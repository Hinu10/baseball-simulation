# Baseball Simulation

昔のファミスタのような親しみやすい野球アクションと、監督としての采配・自動試合シミュレーションを組み合わせたオリジナル野球ゲームです。ブラウザで動く 2.5D の 3D 野球ゲームで、3イニングの CPU 戦を遊べます。

- 球場：Sky Park Stadium（両翼92m・中堅112m）
- 球団：東京コメッツ（Tokyo Comets）・大阪ウルブズ（Osaka Wolves）。どちらも架空の球団です
- 試合モード：**手動**（投げる・打つ・守る・走るを自分で操作）／**監督**（選手は CPU、あなたは方針を指示）／**自動**（CPU 同士を観戦・早送り）。試合中にいつでも切り替えられます（次の投球から反映）

タスクは [Issue](https://github.com/Hinu10/baseball-simulation/issues?q=is%3Aissue) と Milestone [MVP v0.1](https://github.com/Hinu10/baseball-simulation/milestone/1) で管理しています。

### Unity について

最初の計画では Unity（C#）で作る予定でしたが、開発環境に Unity Editor がなかったため、相談のうえ **TypeScript + Three.js + Vite** のブラウザ版に変更しました。Unity は使っていません（Unity のバージョン指定もありません）。仕様にあった Unity の機能は次のように置き換えています。

| Unity の仕様 | このリポジトリでの実装 |
| --- | --- |
| Input System | `src/input/actions.ts` のアクションマップ（キーボード＋Gamepad API） |
| Cinemachine | `src/render/cameraRig.ts`（仮想カメラ3台とブレンド） |
| ScriptableObject | `src/data/teams.json`（読み込み時に検証） |
| MonoBehaviour から独立したロジック | `src/core/`（Three.js にも DOM にも依存しない TypeScript） |
| Unity Test Framework（EditMode / PlayMode） | `npm test`（Node のテストランナーでロジックを検証）／`npm run smoke`（ブラウザを実際にキー操作するテスト） |

## ゲームを起動するまで（はじめての人向け）

1. **Node.js を入れる**
   [nodejs.org](https://nodejs.org/ja) から「LTS」と書かれた版をダウンロードしてインストールします。
   インストールできたか確かめるには、ターミナル（Windows は「PowerShell」）を開いて次を入力します。数字が表示されれば OK です。
   ```sh
   node --version
   ```
2. **このリポジトリをダウンロードする**
   - Git を使う場合：
     ```sh
     git clone https://github.com/Hinu10/baseball-simulation.git
     ```
   - Git を使わない場合：GitHub のページの緑色の「Code」ボタン →「Download ZIP」でダウンロードし、展開します。
3. **フォルダに移動して、必要な部品を入れる**（最初の1回だけ。数十秒かかります）
   ```sh
   cd baseball-simulation
   npm install
   ```
4. **ゲームを起動する**
   ```sh
   npm run dev
   ```
   `Local: http://localhost:5173/` のような行が表示されたら、そのアドレスをブラウザで開きます。
5. メインメニューでチーム・先攻／後攻・モード・CPU の強さを選び、「**プレイボール！**」を押します。
6. やめるときは、ターミナルで `Ctrl + C` を押します。

配布用のファイルを作るときは `npm run build` を実行します。`dist/` フォルダにできたファイルは、`npm run preview` で確認できます（Web サーバーに置けば、Node.js がない PC でもブラウザだけで遊べます）。

## 操作方法

### 投球（守備のとき）
| キー | 操作 |
| --- | --- |
| W A S D | コースを動かす |
| L | 球種を切り替える（ストレート・カーブ・スライダー・フォーク。投手ごとに使える球種が違う） |
| J | 投げる |

### 打撃（攻撃のとき）
| キー | 操作 |
| --- | --- |
| W A S D | ミートカーソルを動かす |
| J | スイング（球が本塁に来る瞬間に） |
| L | ミート ⇔ 強振（強振はカーソルが小さいが、当たれば遠くへ飛ぶ） |
| K | バントの構え |

カーソルの中心より球が上ならフライ、下ならゴロになりやすく、早く振ると引っ張り、遅れると流し打ちになります。CPU の強さ「かんたん」では、投球の通過点に目印が出ます。

### 守備（打球が飛んだら）
| キー | 操作 |
| --- | --- |
| W A S D | 黄色い輪の選手を動かす（赤い印が落下点） |
| J ＋ W / D / A / S | 二塁 / 一塁 / 三塁 / 本塁へ送球（J だけならおすすめの塁） |
| K | ダイビング |
| L | ボールに近い選手に切り替え |

3秒操作しないと、CPU が代わりに動きます。

### 走塁（打ったあと）
| キー | 操作 |
| --- | --- |
| J | 進塁 |
| K | 帰塁 |
| L | 指示する走者を切り替え（全員 → 1人ずつ） |

指示しない走者は CPU が判断して走ります。

### 試合中
| キー | 操作 |
| --- | --- |
| Tab | モード切替（手動 → 監督 → 自動。次の投球から） |
| 1 / 2 / 3 | 監督モードの方針（攻撃：積極・通常・慎重／投球：ストライク優先・通常・際どいコース／走塁：積極・通常・慎重） |
| F | 自動モードの早送り（×1・×2・×4） |
| Esc | ポーズ（モード・方針の変更、試合終了までスキップ、操作説明、メインメニューへ） |

メニューは W/S で選び、A/D で値を変え、J で決定します（マウスでも操作できます）。
ゲームパッド（標準配置）：A＝J、B＝K、X＝L、Y＝F、スタート＝ポーズ、バック＝モード切替、左スティック／十字キー＝WASD。

## 実装済みの機能

- **野球ルール**（`src/core/rules.ts`）：3イニング制、ストライク・ボール・アウト、三振・四球（押し出し）、ファウル（2ストライク後はカウントが増えない、スリーバント失敗）、安打・本塁打・得点、攻守交代、3回裏の省略、サヨナラ、3回終了時の同点は引き分け、第3アウトの種類による得点の扱い（公認野球規則 5.08）
- **投球**（`src/core/pitching.ts`）：4球種、コース指定、球速・コントロール・スタミナ・変化量、制球誤差、疲労、3D の軌道、ストライク判定
- **打撃**（`src/core/batting.ts`）：ミートカーソル、ミート／強振、バント、タイミングと接触位置から打球の初速・角度・方向を計算（結果を乱数で直接決めない）
- **打球物理**（`src/core/ballPhysics.ts`）：重力・簡易な空気抵抗・バウンド・転がり・フェンス・本塁打・エンタイトルツーベース・フェア／ファウル・軌道予測
- **守備・走塁**（`src/core/play.ts`）：捕球担当の選択、ベースカバー、捕球・送球（ボールが実際に飛ぶ）、フォースアウト・タッチアウト・併殺・犠牲フライ、走塁AI（フォース・タッチアップ・次の塁の判断）、人による守備・走塁の操作
- **CPU AI**（`src/core/ai.ts`）：配球、球の見極め（変化球にだまされる）、方針、難易度
- **試合の進行とモード**（`src/core/match.ts`）：手動・監督・自動、次の投球前のモード切替、監督の方針、試合終了までスキップ
- **表示**（`src/render/`）：Sky Park Stadium、3頭身のデフォルメ選手（球団カラー、投球・スイング・走行・捕球・送球・ダイビングの動作）、3つのカメラの自動切替
- **UI**（`src/ui/`）：メインメニュー、HUD（ラインスコア・イニング・BSO・塁状況・打者／投手情報）、カーソル類、送球先ガイド、ポーズ、試合結果、操作説明。設定は端末に保存
- **データ**（`src/data/teams.json`）：2球団、各球団 野手12人・投手3人、能力・打順・先発投手・球団カラー

### ブラウザのスモークテスト（`npm run smoke`）

Vite を起動し、Chrome で実際のページをキーボード操作して、次を確かめます：メインメニューから手動モードの試合開始、コースと球種の変更・投球、CPU の打球と守備（操作しなくてもプレーが終わる）、カメラ A → B → C の切替、先攻での打撃（タイミングよく J を押すと当たる）、監督モードの方針変更、Tab によるモード切替の予約と反映、早送り、ポーズ、試合終了までスキップ、試合結果画面、メインメニューへ戻る、画面サイズの変更、ページのエラーがないこと。

打撃のテストでは、ミートカーソルはテストが球の通過点に直接置き、J キーを押す時刻だけを実際のキー入力で確かめています（カーソルを WASD で合わせる操作はテストしていません）。

### 人の目で確かめたこと

Playwright で撮影した画面を見て、メインメニュー・投球画面（球種・コースカーソル）・打撃画面（ゾーン・ミートカーソル）・守備（操作選手の輪・送球先ガイド）・ポーズ・試合結果の表示を確認しました。

まだ人が実際に通しで遊んで確かめていないもの：操作感（投球の速さ・カーソルの速さ・守備の動かしやすさ）の細かな調整、Windows・Safari・Firefox での表示、ゲームパッドでの操作。

## フォルダ構成と設計

```
src/
  core/        野球のロジック（Three.js・DOM に依存しない）
    field.ts       球場の寸法と座標系（本塁が原点、+z がセンター、+x が一塁側、メートル）
    rules.ts       ルール（試合状態を書き換えるのはここだけ）
    gameState.ts   試合状態
    pitching.ts    投球    batting.ts  打撃    ballPhysics.ts  打球物理
    play.ts        守備・走塁（インプレーの打球1つを時間で進める）
    ai.ts          CPU の投球・打撃    match.ts  試合の進行とモード
    teams.ts       球団・選手データの型と検証
  data/teams.json  球団・選手・打順（コードに書かない）
  render/      3D 表示（球場・選手・カメラ・カーソル）。状態を読んで描くだけ
  ui/          メニュー・HUD・ポーズ・結果（DOM）
  input/       入力のアクションマップ
scripts/smoke.ts   ブラウザのスモークテスト
```

手動・監督・自動のどのモードも同じ進行（`match.ts`）とルール（`rules.ts`）を通り、違うのは「どちらのチームを人が操作するか」だけです。CPU もプレイヤーと同じ命令（投球命令・スイング命令）を出します。
